## 第 3 步 安装依赖

```powershell
cd D:\Learnbuddy\2026-09-18-12-36-17\autograder
npm install
```

**预期**：

- 耗时 **1–3 分钟**
- 中间出现 `added 300+ packages in ...` 之类的汇总行
- 结束后出现 `node_modules` 目录和 `package-lock.json`

**验证**：

```powershell

```

**失败排查**

| 现象 | 原因 | 解决 |
|---|---|---|
| 超过 5 分钟无任何输出 | 源不通 | 回到第 2 步验证 `npm view` |
| `EACCES` / `EPERM` | 写不进本地缓存 | 见下方专项说明 |
| `EBADENGINE` | Node 版本不符 | 换 Node 22 或 24 |
| `UNABLE_TO_VERIFY_LEAF_SIGNATURE` | 代理/证书问题 | `npm config set strict-ssl false`（临时手段） |
| 装着装着报 `network timeout` | 断流 | 直接重跑 `npm install`，npm 会续用缓存 |

重跑是安全的，不用先删 `node_modules`。

### 专项：`EPERM: operation not permitted, open '...\npm-cache\_cacache\index-v5\...'`

这个报错说明 **npm 能联网、能解析依赖，但写不进本地缓存目录**。按顺序试：

```powershell
# 1) 最常见：杀毒软件在扫 npm 缓存。把这两个目录加入白名单
#    C:\Users\Yukii\AppData\Local\npm-cache
#    项目下的 node_modules

# 2) 绕过缓存目录：把缓存改到项目内（项目目录通常不受限）
cd D:\Learnbuddy\2026-09-18-12-36-17\autograder
npm install --cache .\.npm-cache

# 3) 缓存损坏
npm cache clean --force
npm install

# 4) 权限问题（前三条都无效时）
#    用「管理员身份」打开 PowerShell，再执行 npm install
```

> 我在你机器上代跑时正是撞在这条 —— npm 缓存目录在工作区之外，写入被安全策略拒绝。**你自己的终端不会有这层限制**，正常情况下第 1 条就能解决。

## 第 8 步 检查 wrangler.jsonc 里的 D1 绑定

⚠️ **这一步有个坑：`wrangler d1 create` 不是替换，是「追加」。**

它在第 7 步会自动往 `wrangler.jsonc` 里加一条绑定，而且**默认带 `"remote": true`**：

```jsonc
{ "binding": "autograder", "database_name": "autograder",
  "database_id": "df73da3f-...", "remote": true }
```

那条记录有两个问题：

1. `"remote": true` 会让 `wrangler dev` 走 **remote 模式** → 去起 cloudflared 隧道 → 被代理拦截 → **dev server 直接退出**
2. 它和我原先写的 `binding: "DB"` 那条**并存**，而代码读的是 `env.DB` → 指向了那条 `PENDING_CREATE` 的假记录

**正确的最终形态是「只留一条」**：

```jsonc
"d1_databases": [
  {
    "binding": "DB",
    "database_name": "autograder",
    "database_id": "df73da3f-379d-44b8-8c8b-04331bb009a8"
  }
],
```

三个要点：`binding` 必须是 `"DB"`（代码里是 `env.DB`）、`database_id` 用第 7 步拿到的真实值、**不要 `remote` 字段**。

改完保存。**凡是执行过 `wrangler * create` 之后，都应回读一次 `wrangler.jsonc` 确认它没被追加出多余条目。**

## 专项：`localhost 拒绝连接` / `ERR_CONNECTION_REFUSED`

这个报错只有一个含义：**该端口上没有任何进程在监听**。代码无关，先确认服务真的起来了。

### 第一步：确认 dev server 是活着的

看**跑 `npm run dev` 的那个终端窗口**：

| 显示内容 | 含义 | 处理 |
|---|---|---|
| `Ready on http://localhost:8787` | 服务正常 | 问题在地址写法，看第三步 |
| 已经退回命令提示符（`PS D:\...>`） | 进程已退出 | 往上翻，找它的报错 |
| `command not found` / `wrangler 不是内部或外部命令` | 依赖没装成功 | 回到第 3 步重跑 `npm install` |
| 卡住不动 | 可能在编译 | 等 30 秒再看 |

**`npm run dev` 必须一直保持运行**，`curl` 要在**另一个**终端窗口执行。按 `Ctrl+C` 或关掉窗口，服务就没了。

### 第二步：确认端口有监听

```powershell
netstat -ano | findstr :8787
```

- **有输出**（形如 `TCP 127.0.0.1:8787 ... LISTENING`）→ 服务在跑，看第三步
- **无输出** → 服务没起来，回到第一步看那个终端的报错

### 第三步：绕开 IPv6 解析

Windows 上 `localhost` 会优先解析成 IPv6 的 `::1`，而 dev server 默认只绑 IPv4。这会造成「用 `localhost` 拒绝连接、但 `127.0.0.1` 是通的」。

```powershell
curl http://127.0.0.1:8787/health
```

**如果这条通了**，说明代码没问题，只是地址写法。浏览器里改用 `http://127.0.0.1:8787` 即可。

### 第四步：端口被占用

如果 `netstat` 显示监听的是**别的进程**、或启动时报 `Address already in use`：

```powershell
# 换一个端口起
npx wrangler dev --port 8788
```
