# AutoGrader · 智能评阅教学平台

> 把教师脑中的评分标准显性化，并把其中**可机械化**的部分从人身上挪走。

深大计软 & 腾讯云「粤港澳大湾区 AI Coding 创新大赛」参赛作品 · 赛题方向一「AI + 教学管理助手」

## 这个产品解决什么问题

一门计算机专业实验课，100+ 份实验报告，每份人工评阅 10–20 分钟，一学期重复 5–8 轮。

真正的痛点不只是耗时。更要紧的是三件事：

1. **标准会漂移** —— 连批几十份之后，同档位的报告开始拿到不同的分。
2. **扣分说不清** —— "步骤不完整" 这种评语既不能服人，也无法应对成绩申诉。
3. **反馈给不了** —— 200 人的课上，教师给得了分数，给不了个体反馈。

AutoGrader 的设计立场是：**执行问题交给机器，判断问题留给人。**

| 可完全交给机器（执行问题） | 必须留给人（判断问题） |
|---|---|
| 读取与解析文档、代码 | 制定与修改评分标准 |
| 运行代码并核对结果 | 定性判断：创新性、表达质量 |
| 定位评分点对应的原文证据 | 有后果的判定：雷同定性、及格线 |
| 计算相似度信号 | 判断学生真实的理解程度 |
| 聚合班级统计与共性 | 最终确认与签字 |

## 核心设计：观察层与判断层严格分离

这是本项目最不可动摇的一条红线：

> **「没找到」是事实，「不合格」是判断。**

系统先由 AI 抽取**只含事实**的观察层（原文摘录 + 精确位置 + 缺失项 + 表面冲突 + 证据充分性 + 解析失败），再由程序按显式权重确定性算出分数。**模型不参与出分。**

```
评分细则 + 少量手改样本
  → 结构化证据提取（观察层，7 字段，零定性）
  → 带证据引用的自然语言评价
  → 等级匹配（L1–L4）
  → 程序确定性计算分数
  → 教师确认与校准（改档必填 reason_code，沉淀为规则优化信号）
```

### 两道工程护城河

- **引文回查（quoteVerify）** —— 每条原文摘录都必须能在解析文本中真命中，未命中直接丢弃；位置一律以程序计算结果为准，不信任模型给出的字符偏移。这把"防幻觉"从口头承诺变成机器约束。
- **确定性算分** —— `总分 = 100 × Σ(权重 × 档位系数) / Σ权重`。纯函数，可复现、可追溯、可校准。

## 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 部署 | Cloudflare Workers（Free 起步） | 公网可访问；`fetch()` 等待不计 CPU，长耗时 LLM 调用不撞限制。唯一吃 CPU 的本地 PDF 解析走平台服务外移 |
| 批量任务 | Cloudflare Workflows | 单步 wall time 无上限、失败独立重试、可挂起等待教师确认 |
| 模型 | DeepSeek（`deepseek-flash`） | 中文与代码混合输入表现好；JSON Output 模式；成本约 ¥0.1/份 |
| 文档解析 | `unpdf`（PDF）、`mammoth.js`（DOCX），降级 `env.AI.toMarkdown()` | 服务端解析为权威，证据链不可被前端篡改 |
| 存储 | R2（文件与解析产物）+ D1（结构化记录） | 无持久文件系统，产物必须落对象存储 |
| 校验 | Zod | 契约先行，输入输出双向校验 |
| 前端 | Vite + React SPA | 部署为 Workers 静态资源 |

## 两个 LearnBuddy Skill

方案把主链路最核心的两段抽成了可独立调用的 Skill，用于开发期快速迭代 prompt，也用于交付演示。

| Skill | 职责 | 明确不做 |
|---|---|---|
| `autograder-evidence-extract` | 按评分点从报告中抽取可核验证据，输出 7 字段观察层 JSON | 不输出任何评价性词汇，不输出分数 |
| `autograder-level-match` | 依据证据 JSON 与细则档位描述，给出档位建议 | 不输出总分，不修改证据字段 |

**唯一真相源原则**：prompt 正文只维护一份（在 `skills/*/SKILL.md`），Worker 侧导入引用，禁止两处各存一份造成漂移。

## 评测方法

按**评分点**比对，不按总分（总分相近会掩盖逐点错误）。

| 指标 | 阈值 |
|---|---|
| 引文可定位率 | ≥ 0.95（硬门槛） |
| 观察层定性词越界率 | = 0（硬门槛） |
| 二次加权 Kappa（QWK） | ≥ 0.6 可接受 / ≥ 0.8 良好 |
| 逐点档位一致率 | ≥ 65% |
| 总分 MAE | ≤ 5 |

等级是有序变量，因此用 QWK 而非普通 Kappa —— 后者会把「L1 vs L4」与「L1 vs L2」视为同等不一致，严重低估一致性。

评测必须**先让教师盲评**，再与系统结果比对，否则会产生锚定偏差。

## 快速开始

```bash
# 依赖
npm install

# 本地密钥（不要提交）
cp .dev.vars.example .dev.vars
# 编辑 .dev.vars，填入 DEEPSEEK_API_KEY

# 数据库
npx wrangler d1 migrations apply autograder --local

# 开发
npx wrangler dev

# 部署（需 Workers Paid）
npx wrangler secret put DEEPSEEK_API_KEY
npm run deploy
```
